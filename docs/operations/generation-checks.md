# Generation checks

No process holds a generation. A **check** looks at one generation and applies whatever transition is due, as a single conditional write on the row. Concurrent checks are safe because whichever commits first wins and the others match nothing. A check that dies mid-way is redone by the next one.

## What triggers a check

- `GenerationSubmit` checks a generation it just created, which starts its provider call.
- `GenerationGet` checks a generation nobody checked within `CHECK_INTERVAL`. Concurrent polls elect one checker, so a generation reaches the provider at most once per interval however many callers poll it.
- A provider's notification that a call ended checks the generation running it, through the `rest` server. One that arrives before the call's id is recorded finds no generation, and the next poll or sweep settles it.
- The `sweep` server checks the unsettled generations nobody checked within `SWEEP_INTERVAL`, each time a scheduler posts to `/sweep`. A call takes batches of `SWEEP_BATCH_SIZE` while each comes back full, and starts no check its deadline could not wait out. Overlapping calls take disjoint batches. It exists for generations whose caller stopped polling: the provider keeps a finished result only for a while when it does not store it, and only a check frees the concurrency slot of a generation nobody follows.

## What a check does

| Generation                                      | Transition                                                                                                                                                                                             |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Its provider has no connector any more          | Settle `failed`: nothing can run or read its calls.                                                                                                                                                    |
| Pending, due, not cancelled                     | Record start intent, send the payload through the connector, record the call's id, and stop the call if its owner asked to cancel meanwhile.                                                           |
| Provider call known                             | Ask the provider once (cancel it if requested). Settle with its answer when terminal, or requeue a retryable failure while attempts remain, no cancel is requested and the generation is not streamed. |
| Start intent without an id, older than a minute | Settle `failed`: the provider may have accepted the call, so its outcome is unknown. Nothing restarts it.                                                                                              |
| Pending with cancellation requested             | Settle `cancelled`.                                                                                                                                                                                    |

A start that never left, was rate-limited, met a conflict or was refused for this service's credentials costs nothing: its attempt is given back and the start retried 7.5 to 22.5 seconds later, for up to ten minutes after the attempt's first start. Past that, the generation fails, so a request the provider never accepts cannot hold a concurrency slot. The delay is drawn at random, so the starts a burst turned away together come back spread out; a call that failed retryably waits as long before its fresh call. A request the provider rejects, an exhausted quota included, is not retried: the generation fails with the provider's error body for the caller to read. A start whose outcome is ambiguous may have been accepted, so the attempt ends rather than risking a second paid call, and the generation keeps one of its owner's concurrency slots in its purpose for 15 minutes: the provider may still run a call nothing tracks or meters. The global concurrency and the other purposes are not held. A call accepted after its generation settled is cancelled at the provider. A streamed call the provider still reports queued 5 minutes after its start is cancelled the same way, since a creation stream left early can leave it queued for good. A call still running 2 hours after its start is cancelled too, whether its owner asked to cancel it or not, and the generation fails with what it consumed. A stop that fails, or that the provider has not applied yet, is asked again by the next checks for 10 minutes from when it was first wanted, whether on the owner's request, for a streamed call stuck queued or at the run ceiling; then the generation fails all the same, so it never holds a slot forever, but keeps its owner's slot in its purpose for 15 minutes, as an ambiguous start does: the call may still run.

A streamed generation is one provider call: its stream's cursor counts that call's events, and a fresh call would number its own from zero. A retryable failure therefore settles it, and its caller resends it to run it again. Its call is recorded the moment the provider names it, before the creation stream's hold ends, so a process stopped during the hold still tracks the call.

A read the provider refuses for credentials is retried too, since the key is this service's configuration and says nothing about the call. Only a call the provider no longer holds settles as lost. A response larger than 24 MiB is never read: its generation fails and, since the call may still run, keeps its owner's slot in its purpose for 15 minutes. An answer the database keeps refusing to record fails its generation without it, once 2 hours and 10 minutes have passed since the call's start, when a call that cannot be stopped is given up on too.

## Deploying and recovering

Nothing needs draining. A start already sent runs detached from shutdown until the orchestrator kills the process, ten seconds after SIGTERM on Cloud Run, or, for a sweep, until its server's drain ends two seconds earlier. A provider answers a start well within that, so the start is not cut between the provider accepting the call and its id reaching the database, and every write it makes after that carries its own deadline. A sweep stops taking generations once shutdown begins, so it starts no call the kill could cut, and answers when the checks it started end. A replica that dies mid-check leaves a row the next poll or sweep picks up. A stream open on a stopping replica ends with `UNAVAILABLE`, and its caller resumes it after the last event received, on another replica.

The losses that remain are rare. A hard kill (SIGKILL, out of memory, host loss) between the provider accepting a call and its id being written settles that generation `failed` with an unknown outcome, and its answer goes unrecorded. A start the provider is still answering when the orchestrator kills a stopping process ends the same way. A database too unavailable to record the id or to read the row back does the same. A server has CPU only while it handles a request, so a check whose caller gave up waits for the server's next request, and a start the provider answered meanwhile ends the same way once its deadline has passed. A streamed submit or poll given a deadline of at least 35 seconds is never given up mid-start. A write of the id that got no answer is tried once more, since the database may still commit it; then a call the generation is seen not to carry is stopped, but one it cannot be read for is left to run.

## Providers and keys

A generation runs on the provider named in its submission, through that provider's connector, until it settles. Its payload is in that provider's format, so it never moves to another provider.

Rotating the OpenAI key within one account changes `OPENAI_API_KEY` alone: calls in flight stay readable, and nothing is lost. Pointing the connector at another account or endpoint abandons the calls in flight, since the new credentials cannot read the old account's operations: their next check settles them as lost, and a resend pays again. Make that change while nothing runs, or accept the cost. A deployment that drops a connector fails the generations still running on its provider.
