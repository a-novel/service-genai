# Upgrading to v0.7.0

A generation's times are protobuf `Timestamp`s, and the queue's age is a protobuf `Duration`. Both keep their full precision.

## Do I need to act?

**Required** for callers that read a generation's times or the queue's age: those fields change type, and the queue's age changes name. A caller that reads neither takes the release as is.

**No** for operators: the database and the configuration are unchanged.

## Read the generation's times as Timestamps

| Field on `Generation`      | v0.6                                                | v0.7                                                            |
| -------------------------- | --------------------------------------------------- | --------------------------------------------------------------- |
| `created_at`, `updated_at` | RFC 3339 string                                     | `google.protobuf.Timestamp`                                     |
| `settled_at`, `expires_at` | RFC 3339 string, empty until the generation settles | `google.protobuf.Timestamp`, unset until the generation settles |

The fields keep their names and take the numbers 18 to 21. Their former numbers, 9 to 12, are reserved. In Go, read them with `AsTime`:

```go
// v0.6
createdAt, err := time.Parse(time.RFC3339Nano, generation.GetCreatedAt())

if generation.GetSettledAt() != "" {
	settledAt, err := time.Parse(time.RFC3339Nano, generation.GetSettledAt())
}

// v0.7
createdAt := generation.GetCreatedAt().AsTime()

if generation.GetSettledAt() != nil {
	settledAt := generation.GetSettledAt().AsTime()
}
```

`AsTime` reads an unset `Timestamp` as the Unix epoch, so check `settled_at` and `expires_at` for `nil` first. The getters return `*timestamppb.Timestamp`, from `google.golang.org/protobuf/types/known/timestamppb`.

The JSON form of a `Timestamp` is an RFC 3339 string in UTC, such as `"2026-01-01T00:00:00.123456Z"`, so `grpcurl` still prints each time as an RFC 3339 string.

## Read the queue's age as a Duration

`QueueDepth.oldest_pending_age_seconds`, a `double` of seconds, becomes `QueueDepth.oldest_pending_age`, a `google.protobuf.Duration` numbered 3. The former number 2 and name are reserved. The age is still zero when nothing is pending.

```go
// v0.6
age := time.Duration(depth.GetOldestPendingAgeSeconds() * float64(time.Second))

// v0.7
age := depth.GetOldestPendingAge().AsDuration()
```

The getter returns `*durationpb.Duration`, from `google.golang.org/protobuf/types/known/durationpb`. The JSON form of a `Duration` is a number of seconds with an `s` suffix, such as `"90.250s"`.

## Roll out and verify

Deploy the v0.7.0 server before the callers built on its client. Neither side rejects the other's messages, but each reads the other's fields as missing: a v0.6 client reads every time as an empty string and the queue's age as zero, and a v0.7 client reads a v0.6 server's times and queue age as unset.

To verify, submit a generation and read it back: `created_at` carries its fractional seconds.
