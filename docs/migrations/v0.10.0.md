# Upgrading to v0.10.0

The caller owns every cap: the caps file and its user tiers are gone, and a submit without caps is not limited. The `rest` server, which received OpenAI's webhook notifications, is gone too: polls and the sweep check every generation. The service stops using the generation columns and the payload table that the next release drops.

## Do I need to act?

**Required** for callers: send each user's caps on every submit before you upgrade, and stop sending `user_tier`.

**Required** for operators that run a `rest` deployment or build their image with their own caps file. Every operator deploys this release everywhere before the next one, whose migrations drop what this one stopped using.

The migration changes a column default and runs in seconds.

## Send caps on every submit

A submit without `caps` used to answer to the caps file, its `user_tier` selecting the limits on the purpose and across every purpose. Now a submit answers to its own `caps` alone, on its purpose, and a submit without caps, or with empty caps, is not limited. Send each user's caps with every submit before you upgrade, as [v0.9.0](v0.9.0.md#send-each-users-caps) describes:

```go
request.Caps = &servicegenai.GenerationCaps{
	Concurrency: proto.Int32(2),
	Windows: []*servicegenai.GenerationCapWindow{
		{Duration: durationpb.New(5 * time.Hour), InputTokens: proto.Int64(2_000_000)},
		{Duration: durationpb.New(720 * time.Hour), OutputTokens: proto.Int64(5_000_000)},
	},
}
```

`GenerationSubmitRequest.user_tier` is removed, and its field number is reserved. Delete it from your requests: the Go client no longer has the field, and the server ignores it on the wire. A refusal's `google.rpc.QuotaFailure` subject is always `purpose "<name>"`, never `global`.

The service still declares the purposes a caller may submit, in `internal/config/purposes.config.yaml`, and refuses a submit or a usage summary naming any other with `INVALID_ARGUMENT`. `studio.generation` stays declared.

## Remove the rest server

The `rest` image is no longer published. If you run it:

1. Delete the webhook endpoint pointing at `https://<host>/webhooks/openai` in the OpenAI project's settings, so OpenAI stops delivering notifications to it.
2. Remove the `rest` deployment and its public route.
3. Remove `OPENAI_WEBHOOK_SECRET` and the secret that holds it.

Nothing replaces it: every poll checks an unsettled generation with the provider, and the sweep checks the generations nobody polls. The `sweep` server keeps every `REST_*` variable it read.

## Stop shipping a caps file

`internal/config/caps.config.yaml` is gone, with its tiers. An image built with its own caps file builds without it: move its purposes to `internal/config/purposes.config.yaml`, a YAML list of names, and send its limits as caps from the caller.

## Deploy this release everywhere first

The next release drops `generations.checked_at`, `run_at`, `attempt`, `max_attempts` and `first_start_requested_at`, and the `generation_payloads` table. Its migrations run while the servers of the release before it still serve. This release names none of them, and v0.9.0 names them all, so deploy this release to every environment before you take the next one.

## Operators

- Run the migrations job, then deploy the servers. The migration sets `generations.attempt` to default to 1, so a v0.9.0 replica can record the answer of a generation this release inserted. It changes the catalog only, under a lock held as long as that takes.
- While v0.9.0 replicas still run, a submit they serve without caps still answers to their caps file. Once every replica runs this release, no submit without caps is limited.
- The sweep's `REST_RATE_LIMIT` defaults to golib's `5/1s` instead of `500/1s`, which only the notifications needed. A sweep running on `SWEEP_TICKER` takes no requests but its ping, which skips the limit. If a scheduler posts `/sweep` more than five times a second, set the variable.

## Roll out and verify

To verify, submit a generation with caps past a limit you set, and read the `RESOURCE_EXHAUSTED` refusal naming the purpose. Submit one without caps, and it is admitted.
