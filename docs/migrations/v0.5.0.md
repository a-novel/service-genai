# Upgrading to v0.5.0

Callers describe a generation in provider-neutral terms and never name a model, and no process holds a generation any more. Submitting starts the provider call, each `GenerationGet` checks a stale generation with the provider, and a sweep checks the generations nobody polled. The worker and the reaper are gone.

## Do I need to act?

**Required** for callers: the submit request and the generation change shape, and `GenerationWatch` and `UsageQuery` are removed.

**Required** for operators: the database schema is replaced, the worker and reaper settings are removed, and the provider settings are renamed.

## Submit a provider-neutral request

| Removed from `GenerationSubmitRequest`  | Replacement                                                                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `request`, the OpenAI Responses payload | `tier`, `instructions` (trusted), `input` (untrusted, any JSON value) and `output_schema` (within OpenAI's strict-mode subset). The service picks the model, the effort and the output ceiling for the Tier. |
| `max_attempts`                          | The `MAX_ATTEMPTS` service setting (`2`).                                                                                                                                                                    |
| `idempotency_key`                       | Nothing: the service derives the key from the request and the owner. To recover after a crash, resend the same request. To ask for another result of a request that succeeded, send the next `variant`.      |

A failed or cancelled generation is not served again: resending its request runs it from scratch. Drop any key you persisted for crash recovery.

`TierList` is new: it reports each Tier's input and output token ceilings, so you can size the input and the schema before submitting. An input past the ceiling fails the generation as `INVALID_REQUEST`.

Input and schema must be I-JSON ([RFC 7493](https://www.rfc-editor.org/rfc/rfc7493)): valid UTF-8, no unpaired surrogates, no duplicate names in an object. The schema must be a JSON object, and `purpose` at most 255 characters. A request that breaks a rule answers `INVALID_ARGUMENT` with the reason.

## Read the generation

| Removed from `Generation`           | Replacement                                                                                                                                              |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `output` as the provider's envelope | `output` is the document conforming to `output_schema`. Drop any Responses parsing, `ExtractResponsesOutputText` included.                               |
| `error` as an opaque reason         | `failure` says what kind of failure ended it (`REFUSED`, `INCOMPLETE`, `INVALID_REQUEST`, `FAILED`), and `error` names the cause in the service's words. |
| `attempt`, `max_attempts`           | `usage` lists each provider call: its attempt, the provider, model and reasoning effort that actually ran, and its tokens, cache writes included.        |

## Cancel is idempotent

Cancelling a generation that already settled returns it as it stands, with `OK`, instead of `NOT_FOUND`. A retried cancel, or one that lost a race with completion, still succeeds: read the returned status to know whether it was cancelled. `NOT_FOUND` now means only that the owner has no such generation.

## Poll instead of watching

`GenerationWatch` is removed: poll `GenerationGet` on your own interval until the generation settles. A polled generation moves at the caller's pace; an unpolled one waits for the sweep, up to one `SWEEP_INTERVAL`.

## Keep usage yourself

`UsageQuery` is removed. Read `usage` off each generation and keep the long-term record on your side: the service purges usage with the generation it describes.

## Recreate the database

The migrations are replaced by a baseline, `20261008191734_generations`, followed by `20261008203824_generation_failures`, `20261008210623_generation_request_keys`, `20261008212809_generation_providers` and `20261008223921_generation_usage_cache_writes`. No environment ran service-genai before this release, so there is no data to carry over: start the `database` image on a fresh volume, then run the migrations job. A data directory from the earlier image is not portable to the new one, and lacks the settings the retention purge needs.

## Replace the configuration

| Removed                                                                                     | Replacement                                                                                          |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `WORKER_ID`, `WORKER_INTERVAL`, `WORKER_LEASE`, `WORKER_BATCH_SIZE`, `WORKER_POLL_INTERVAL` | `CHECK_INTERVAL` (`2s`)                                                                              |
| `REAPER_INTERVAL`, `REAPER_GRACE`, `REAPER_BATCH_SIZE`                                      | `SWEEP_INTERVAL` (`1m`), `SWEEP_BATCH_SIZE` (`50`)                                                   |
| —                                                                                           | `MAX_ATTEMPTS` (`2`), replacing the request's `max_attempts`                                         |
| `RETENTION` default `168h`                                                                  | `RETENTION` default `6h`: a settled generation, its usage and its request key are purged together    |
| `OPENAI_API_KEY`                                                                            | `PROVIDER_API_KEY`, now required: the server refuses to start without it                             |
| `OPENAI_BASE_URL`                                                                           | `PROVIDER_BASE_URL` (`https://api.openai.com/v1/`)                                                   |
| —                                                                                           | `PROVIDER_NAME` (`openai`), `PROVIDER_EPOCH` (`1`), `PROVIDER_TIERS` (the committed OpenAI bindings) |

`GRPC_TIMEOUT_SHUTDOWN` now defaults to `8s`, inside Cloud Run's ten seconds between SIGTERM and SIGKILL. Keep any override under your orchestrator's kill delay.

## Status changes

`GENERATION_STATUS_ABANDONED` is removed. A generation whose process died is picked up by the next check instead.

## Roll out and verify

A rolling deploy is safe at any time: a check runs for seconds, and anything it did not finish is redone by the next one.

In a test environment, submit a generation, stop the server while it runs, start it again, and poll: the generation settles once, with one usage row per provider call.
