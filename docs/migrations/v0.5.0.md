# Upgrading to v0.5.0

Callers describe a generation in provider-neutral terms and never name a model, and no process holds a generation any more. Submitting starts the provider call, each `GenerationGet` checks a stale generation with the provider, and a sweep checks the generations nobody polled. The worker and the reaper are gone.

## Do I need to act?

**Required** for callers: the submit request and the generation change shape, and `GenerationWatch` and `UsageQuery` are removed.

**Required** for operators: the database schema is replaced, and the worker and reaper settings are removed.

## Submit a provider-neutral request

| Removed from `GenerationSubmitRequest`  | Replacement                                                                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `request`, the OpenAI Responses payload | `tier`, `instructions` (trusted), `input` (untrusted, any JSON value) and `output_schema` (within OpenAI's strict-mode subset). The service picks the model, the effort and the output ceiling for the Tier. |
| `max_attempts`                          | The `MAX_ATTEMPTS` service setting (`2`).                                                                                                                                                                    |

## Read the generation

| Removed from `Generation`           | Replacement                                                                                                                                              |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `output` as the provider's envelope | `output` is the document conforming to `output_schema`. Drop any Responses parsing, `ExtractResponsesOutputText` included.                               |
| `error` as an opaque reason         | `failure` says what kind of failure ended it (`REFUSED`, `INCOMPLETE`, `INVALID_REQUEST`, `FAILED`), and `error` names the cause in the service's words. |
| `attempt`, `max_attempts`           | `usage` lists each provider call: its attempt, the provider, model and reasoning effort that actually ran, and its tokens.                               |

## Poll instead of watching

`GenerationWatch` is removed: poll `GenerationGet` on your own interval until the generation settles. A polled generation moves at the caller's pace; an unpolled one waits for the sweep, up to one `SWEEP_INTERVAL`.

## Keep usage yourself

`UsageQuery` is removed. Read `usage` off each generation and keep the long-term record on your side: the service purges usage with the generation it describes.

## Recreate the database

The migrations are replaced by a baseline, `20261008191734_generations`, followed by `20261008203824_generation_failures`. No environment ran service-genai before this release, so there is no data to carry over: recreate the database, or drop the `generations` and `generation_usage` tables and the `generation_status` type, then run the migrations job.

## Replace the configuration

| Removed                                                                                     | Replacement                                                  |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `WORKER_ID`, `WORKER_INTERVAL`, `WORKER_LEASE`, `WORKER_BATCH_SIZE`, `WORKER_POLL_INTERVAL` | `CHECK_INTERVAL` (`2s`)                                      |
| `REAPER_INTERVAL`, `REAPER_GRACE`, `REAPER_BATCH_SIZE`                                      | `SWEEP_INTERVAL` (`1m`), `SWEEP_BATCH_SIZE` (`50`)           |
| —                                                                                           | `MAX_ATTEMPTS` (`2`), replacing the request's `max_attempts` |

`GRPC_TIMEOUT_SHUTDOWN` now defaults to `8s`, inside Cloud Run's ten seconds between SIGTERM and SIGKILL. Keep any override under your orchestrator's kill delay.

## Status changes

`GENERATION_STATUS_ABANDONED` is removed. A generation whose process died is picked up by the next check instead.

## Roll out and verify

A rolling deploy is safe at any time: a check runs for seconds, finishes inside the shutdown budget, and anything it did not finish is redone by the next one.

In a test environment, submit a generation, stop the server while it runs, start it again, and poll: the generation settles once, with one usage row per provider call.
